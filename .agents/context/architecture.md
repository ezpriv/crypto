# Architecture

## Layout

```
src/sodium.ts         interface Sodium: the libsodium functions the package calls, and nothing else
src/index.ts          createCrypto(sodium) → every function; frame(); constants (version byte, Argon2id floor and cap)
test/crypto.test.ts   Vitest on libsodium-wrappers-sumo: vectors, round trips, refusals
vectors/vectors.json  fixed inputs and outputs; regenerated by scripts/make-vectors.ts
scripts/              make-vectors.ts, check-pins.ts (run with Node's type stripping)
ports/swift/          Swift package: openSealed on swift-sodium, tested against the vectors
ports/kotlin/         openSealed on lazysodium-android, one file, no build yet
SPEC.md               the wire format; the source of truth for every port
```

## How it fits together
- **Injection, not imports.** `src/` never imports libsodium. The caller passes a module that satisfies `Sodium`, so the same code runs in Metro (native and web), service workers and Node. `react-native-libsodium` must be imported as a namespace (`import * as sodium`): its default export lacks `crypto_box_seal` on native.
- **Associated data is a string.** `react-native-libsodium` throws on anything else on native, so `frame()` builds netstrings and both bindings encode them as UTF-8.
- **Two ciphertext kinds plus one composite** (`SPEC.md`): Encrypted (XChaCha20-Poly1305), Sealed (`crypto_box_seal` with a framed header checked on open), and Linked (Encrypted under the QR secret, inside a Sealed box).
- **Errors** are plain `Error`s whose message starts with `ezpriv:`. libsodium's own errors are caught and replaced, so callers see the same messages on every runtime.
- **Bytes in, bytes out.** Every function takes and returns `Uint8Array`; encoding is the app's job.

## Ports
The iOS Notification Service Extension and the Android `FirebaseMessagingService` can't run JavaScript, so `ports/` re-implements only `openSealed` (context `notification` via `ezpriv/user`). A port is correct when it passes `vectors/vectors.json`.

## CI and release (`.github/workflows/`)

| Workflow | Jobs | Notes |
|---|---|---|
| `ci.yml` (PRs and pushes to `main`) | `trivy` (lockfile CVEs, secrets, misconfig; fails on fixable HIGH/CRITICAL), `lint` (`biome ci`, `check-pins`), `test` (types, Vitest, build), `swift` (`swift test` on macOS), `ci` (fails unless all passed: the one check to require on `main`) | Every action pinned to a commit SHA |
| `release.yml` (pushes to `main`) | `build` (install, test, build, `npm pack`, upload the tarball) → `publish` (environment `npm`, `id-token: write`, downloads the tarball, `npm publish --ignore-scripts` if that version isn't on npm) | The publish job runs no code from the repo or its dependencies. A compromised dev dependency in `build` could still alter the tarball |

- **Trusted publishing:** npm's trust entry for `@ezpriv/crypto` names `ezpriv/crypto` and `release.yml`. No npm token exists anywhere.
- **Versioning:** semver in `package.json`. Before 1.0, a breaking change bumps the minor (`0.0.1` → `0.1.0`). Merging a new version to `main` publishes it. Format changes also need a new label or version byte (`SPEC.md`).
